# 行内夹注（双行注）

> 总纲见 [overview_zh_CN.md](overview_zh_CN.md)。本册只描述 `-hutu-note-placement: inline`。

## 1. 触发与结构

```css
.note { -hutu-note-placement: inline; }
```

```html
<p>正文<span class="note">注文内容</span>正文</p>
```

- 注文元素必须处于行内格式化上下文中。
- 一个注文元素生成**一个**夹注盒；夹注盒内部固定为两条子行。
- 注文盒排在注文元素所在的 DOM 位置：即紧接在它前面的行内内容之后、后面的行内内容之前。
- 每条子行都是一个普通行盒，使用普通行内排版、字形整形和基线计算；夹注不引入额外的字形网格。
- 夹注可以跨外层行；每个外层片段内部仍只有两条子行。
- 本节规则适用于任意文字系统，不限于 CJK。比例字体、连字、组合字符、emoji、RTL 和复杂文字整形都按普通行布局处理。
- 子行排版必须复用普通行内排版核心。标点禁则、断行机会、bidi、`text-autospace`、`text-spacing-trim`、`hanging-punctuation` 和装饰绘制不得另写一套；夹注只覆盖可用 inline 尺寸、两行结构和落位方式，不另算字号或行高。

## 2. 几何

### 2.1 记号

- `n`：当前片段的注文按 `white-space` 处理后的排版字符数（按字素簇计，组合符号随基字）。
- `L`：外层格式化上下文的正文 **strut 行高**（used `line-height`），只用于计算外层行间空隙。
- `F`：正文 strut 的实际字号（used `font-size`）。
- `G`：正文保留的行间空隙，`G = max(0, (L - F) / 2)`。
- `H1`、`H2`：第一条、第二条子行按普通行布局得到的实际 block 尺寸。
- `w`：当前片段两条子行实际测量宽度的较大值。
- `B`：当前片段注文盒的 margin box block 尺寸。
- `H0`：不含注文时，该外层行由正文 strut 和其它非注文内容得到的已用行高。
- `J`：当前注文片段在外层行中可用的 inline 宽度，即外层行内容宽度扣除缩进和注文之前已有内容后的剩余宽度。

### 2.2 字号与行高

- 夹注**不定义**自己的 `f`／`h` 计算公式。注文元素及其内部内容的 `font-size`、`line-height` 完全按普通 CSS 级联、继承和 computed value 规则取得。
- 作者声明时使用声明值；未声明时使用普通继承值。不得用外层 `L` 再派生字号或行高，也不得把注文字号截断到 `L / 2`。
- `line-height: normal` 按其普通规则解析为实际像素值。
- 每条子行按普通行布局使用其中各 run 自己的 computed `font-size`／`line-height`。因此嵌套元素直接声明的尺寸只影响它自身的 run，并按普通行高规则参与该子行的 `H1` 或 `H2`。
- 空子行没有文字 run 时，以注文元素自身的 computed `line-height` 作为该行的基础高度。
- 夹注的 margin box block 尺寸参与外层行高。`B ≤ H0` 时最终行高仍为 `H0`；只有 `B > H0` 时，才由夹注撑高该行。
- 当 `B > H0` 时，最终行高为 `B + 2G`：注文 margin box 的 block-start 和 block-end 两侧各保留完整的 `G`，注文仍在行盒中心。相邻两条被夹注撑高的外层行之间因此有 `2G` 空隙，注文不会贴满整条行带。
- 需要传统双行夹注比例时，由作者正常声明较小字号和合适行高，例如 `font-size: 0.5em`；引擎不再替作者推断。

### 2.3 尺寸

| 量 | 值 |
|---|---|
| 每子行 inline 尺寸 | 按普通行内排版测得的该子行宽度 |
| 片段内容 inline 自然尺寸 | `w = max(第一子行宽度, 第二子行宽度)`；行尾 justify 后按 §2.7 改为 `J` 扣除装饰后的宽度 |
| 片段 border box inline 尺寸 | `w` + 该片段承担的 inline padding／border |
| 片段 margin box inline 尺寸 | border box inline 尺寸 + 该片段承担的 inline margin |
| 每子行 block 尺寸 | 第一子行 `H1`、第二子行 `H2`，均由普通行布局得到 |
| 片段内容 block 尺寸 | `H1 + H2` |
| 片段 border box block 尺寸 | `H1 + H2` + block padding／border |
| 片段 margin box block 尺寸 | border box block 尺寸 + block margin |

- 两子行都按普通行布局测量宽度；通常较短的一行在 inline-end 留空，不拉伸、不补字形。只有该片段真正到达外层行尾且外层行适用两端对齐时，才按 §2.7 拉齐。
- CJK 等宽文本下，实测平衡会退化为第一子行约 `ceil(n / 2)` 字、第二子行约 `floor(n / 2)` 字，因此单片段推进通常为 `ceil(n / 2) × f`。这只是等宽文本的算术特例；任何非等宽文本都必须使用实际测量宽度。
- 跨行且无装饰时，总推进是各片段内容宽度之和 `Σ w_i`；有装饰时按 §2.5 使用各片段 margin box 的 inline 尺寸累加。每个片段独立重新测量平衡点。
- 两子行沿 block 轴并排：第一子行靠 **block-start**（竖排为右列，横排为上行），第二子行靠 **block-end**（竖排为左列，横排为下行）。
- 默认装饰下，注文盒的 margin box block 中心与注文所在行盒的 block 中心重合。
- 注文盒是否撑高正文行由实际 `H1 + H2` 和装饰决定；不再假设两条子行都等于某个统一的 `h`。

### 2.4 字符分配

- 不对半数字符串。先用普通行内测量的逐字素前进量累计定位两行平衡点，再用完整普通行布局在平衡点附近精测“边界之前”和“边界之后”两条子行，选择使 `max(第一子行宽度, 第二子行宽度)` 最小的切分点。累计测量只负责缩小搜索范围，最终切分必须由完整行布局复核。
- 如果估算平衡点附近的边界全部被标点禁则封死，必须向两侧搜索最近的合法边界；不得因为相邻候选非法就退化为把整段放进第一子行。
- 若有多个切分点得到同一最大宽度，优先把更多字素簇放在第一子行；仍然相同则取更靠后的边界。这样等宽 CJK 自然回退为第一子行 `ceil(n / 2)`、第二子行 `floor(n / 2)`，宽窄字符混排则按真实字宽平衡。
- 切分点还必须通过普通 `LineBreaks` 标点禁则：逗号、句号、收尾括号等不得因双行分配或外层片段分配而落到新行行首；行首括号、引号等也不得被留在上一行行尾。单词内部不要求保留普通词边界，但标点和空白边界必须遵守普通行规则。
- 宽度相同的两子行在 inline 起点对齐；较短的一行仍在 inline-end 留空，除非片段的实际行尾条件触发 §2.7 两端对齐。
- “第一半”按逻辑顺序的字素簇计算，不按视觉顺序；RTL 文本在每条子行内部再由 bidi 重排。
- 实测切分发生在字素簇边界，可以切断拉丁词等连续文本；每条子行随后按普通行内规则整形，但不在片段内部再次折行。禁止二次折行是行构建器的一项布局约束，**不得**通过把 `white-space` 改成 `nowrap` 实现；作者的折叠、保留空格和强制换行语义必须原样保留。

### 2.5 盒装饰与跨片段

注文盒按普通 inline 盒的分片模型处理。`margin`、`padding`、`border` 参与几何，`background` 按 border box 绘制；默认使用 `box-decoration-break: slice`：

- **单片段**：片段同时承担 inline-start、inline-end 以及 block-start、block-end 的全部装饰。
- **多片段**：
  - 第一个片段只承担 inline-start 的 margin／padding／border；
  - 最后一个片段只承担 inline-end 的 margin／padding／border；
  - 中间片段不承担 inline-start／end 的 margin／padding／border；
  - 每个片段都承担自己的 block-start／block-end margin／padding／border。
- `box-decoration-break: clone` 时，每个片段都承担完整的 inline-start／end 与 block-start／end 装饰。
- 背景和边框按片段绘制；box-decoration-break 为 `slice` 时，首尾边缘只在整条注文的首尾出现。
- 装饰不改变 `f` 和 `h`，只改变片段的 border box、margin box、推进和绘制范围。
- 装饰后的 margin box block 尺寸参与 §2.3 的外层行高计算：大于 `H0` 时所在行增高，而不是让装饰永久溢出正文行。

### 2.6 前后空隙

- 默认**无空隙**：注文盒紧接前一行内内容，后一行内内容紧接注文盒。
- 作者在注文元素上声明的 `margin`／`padding`／`border` 按 §2.5 加入推进；此时空隙由作者负责。

### 2.7 行尾对齐与悬挂

- “夹注到达外层行尾”指该注文片段因剩余空间不足以继续容纳下一个允许的字素单元，被截断到下一条外层行；即使还剩下一点不足以容纳下一单元的空间，也算到达行尾。若片段是这条最终外层行最后一个仍有墨迹的 in-flow 行内内容，后面只剩可折叠空白、零宽盒或没有内容，同样视为到达行尾。
- 只有到达外层行尾的片段才允许对子行做两端对齐和标点悬挂。夹注后面还有正文、图片或其它可见行内内容时，不施加这两项行尾效果。
- 外层行按 `text-align`／`text-align-last` 的普通规则会两端对齐时，片段的每条非空子行以 `J` 为目标拉齐；注文自身的 inline margin／padding／border 先从 `J` 中扣除，得到两条子行可用的内容宽度。较短子行中的词间空隙或允许的 CJK 字符间隙被拉开，较长子行也继续拉开到同一目标，不得只对齐到自然宽度 `w` 后把余量留在注文外。`text-align-last: auto` 仍按普通规则处理：最后一行或强制换行行上的 `text-align: justify` 不自动变成两端对齐，除非 `text-align-last: justify`。
- 特例：若外层行中所有可见内容都是夹注，则这条行就是纯夹注行。只有在该行不是格式化上下文的最后一行、也不是强制换行行时，`text-align: justify` 才必须把该注文的 margin box 拉到外层行尾，两条子行随后都填满扣除装饰后的注文内容宽度。
- 纯夹注行如果就是最后一行，`text-align-last: auto` 与普通行一样让它保持自然宽度，不执行 justify；只有显式声明 `text-align-last: justify` 时才拉满。标点悬挂仍按下面的行尾规则处理。
- 到达行尾时，子行按普通 `hanging-punctuation`、`text-spacing-trim` 和自身书写模式处理边缘标点；未到达行尾时，不把标点悬挂到夹注盒外，也不为了行尾对齐拉宽子行。
- 纯夹注行视为夹注自身的最后格式化行，因此 `hanging-punctuation: last`、`force-end` 和 `allow-end` 都按该行尾条件生效，即使它还是外层段落的最后一行或末尾仍有行盒空白。
- 行尾处理可能减少片段实际 inline 推进，外层行随后按处理后的片段宽度重新对齐。

## 3. 断行与片段

1. 在当前外层行的剩余 inline 空间中，取能在两条普通子行内排下的**最大字素簇前缀**。
   计算该空间时必须使用外层行最终记账口径下的当前已用宽度，不得使用仍包含临时悬挂补偿或行盒估算差的 wrapping 宽度；首行缩进另行扣除。
2. 用逐字素实测前进量定位平衡边界，再用完整行布局精测相邻边界，按 §2.4 选择 `max(第一子行宽度, 第二子行宽度)` 最小的切分点。
3. 两条子行必须各自在剩余 inline 空间内排成一行；夹注片段内部不再二次折行。
4. 片段的自然 inline 推进取两条子行实际测量宽度的较大值，再加该片段应承担的装饰；只有触发 §2.7 的行尾 justify 时才继续扩到外层行尾。
5. 当前外层行已有内容、但连一个字符的片段都放不下时，整个片段移到下一外层行。
6. 空外层行仍放不下一个字符时，放置一个字符并允许 inline 溢出，以保证排版总能向前推进。
7. 剩余注文从下一片段继续，重复上述过程；夹注不限长，可以跨任意多行／多列。
8. 每个片段独立实测平衡；双行切分点和外层片段切分点都必须通过普通标点禁则。片段之间的阅读顺序为：片段 1 第一子行 → 片段 1 第二子行 → 片段 2 第一子行 → ……，与 DOM 顺序一致。

### 3.1 示例

正文 `font-size: 16px`、`line-height: 24px`；作者为注文声明 `font-size: 8px`，未声明 `line-height`：

- 子行字号使用声明的 `8px`；`line-height` 按普通继承得到 `24px`，而不是重新算成 `L / 2`。
- 两条子行各 `24px`，片段内容 block 尺寸为 `H1 + H2 = 48px`。
- 注文 7 字：第一子行 4 字、第二子行 3 字；等宽 CJK 下宽度分别为 `32px` 和 `24px`，片段推进为 `32px`。
- 若当前行只能容纳 3 个等宽字符的子行：片段 1 取 6 字（3 + 3），片段 2 取 1 字（1 + 0）。

## 4. 边界情况

| 情况 | 行为 |
|---|---|
| `n = 0` | 不生成注文盒，等价于 `none` |
| `n = 1` | 第一子行 1 字，第二子行空；第二子行仍按注文自身的 computed `line-height` 保留基础高度 |
| 奇数字 | 等宽字体下第一子行约多一字；比例字体按实测宽度决定实际字素数 |
| 连续空格 | 按 `white-space` 的折叠规则处理后再计 `n` |
| 注文内有 `<br>` | 结束当前外层片段；后续内容从下一片段继续，并在该片段内重新实测平衡 |
| 源文件中的换行与缩进 | 与普通文字一样先由 `white-space` 处理，不得把格式化缩进当成 `<br>`；只有 `<br>` 以及保留模式下的分段符结束外层片段 |
| 注文内有 ruby | V1 不要求支持；作者应避免在夹注内使用 ruby。若引擎仍将其排入，注音不属于本规范的布局保证。 |
| 注文出现在 `rt` 内 | `-hutu-note-placement` 不生效，按 `none` 处理 |
| 注文内有嵌套注文 | 内层 `interline` 提升到外层夹注片段所在正文行的注文流；其余嵌套注文不生效，按普通行内内容排 |
| RTL 文本 | 每条子行按普通 bidi 规则排版；子行顺序仍按 block-start／end（见总纲 §8） |
| 组合字符／emoji | 一个扩展字素簇算一个字符，不拆开组合序列或 ZWJ 序列 |
| 比例字体／复杂文字 | 两子行分别按普通 shaping 测量；字符数多的一行不一定更宽 |

## 5. 与其它特性的交互

- **行高**：夹注参与注文所在行的行高计算。`B ≤ H0` 时保持 `H0`；`B > H0` 时使用 `B + 2G`，在注文前后各保留完整的正文行间空隙 `G`。
- **`text-emphasis`**：按普通行内布局在子行内排版。
- **`text-decoration`**：按普通行内盒和片段规则绘制；默认 `box-decoration-break: slice`。
- **`text-spacing-trim` / `hanging-punctuation`**：仅当注文片段到达外层行尾时，在每条子行内按普通行尾规则处理；中途片段不悬挂。
- **`text-align` / `text-align-last`**：仅当注文片段到达外层行尾且外层行按普通规则需要 justify 时，子行在外层行剩余宽度 `J` 扣除注文装饰后两端对齐；纯夹注行只有不是最后一行时才铺满外层行尾。中途片段和最后一行保持自然宽度和起点对齐。
- **`text-combine-upright`**：在每条子行内按普通行规则处理。
- **竖排字形方向**：包含 CJK 字符的子行强制直立（`text-orientation: upright`），不随嵌套样式或字体判定横倒；纯西文子行仍按普通竖排规则处理。
- **浮动与绝对定位**：注文元素上的 `float`／`position` 被忽略。
- **嵌套行间注**：夹注内部声明的行间注提升到正文层；夹注自身仍固定为两条子行，不得在内部插入行间注流。

## 6. 验收点

验收点与测试类型如下：

> 类型标记：**探针** = 数值几何断言；**Reftest** = 与参考页做带文字抗锯齿容差的截图比较；**探针 + Reftest** = 两者均必须。

1. **探针 + Reftest**：未触发行尾 justify 时，单片段注文盒的 inline 推进 = `max(第一子行宽度, 第二子行宽度)`（默认装饰下）；等宽 CJK 下退化为 `ceil(n/2) × f`；跨行时按片段累加。
2. **探针**：片段内容 block 尺寸 = `H1 + H2`；border box 和 margin box 按 §2.3、§2.5 加上装饰。`H1`、`H2` 必须来自普通 CSS computed 尺寸和普通行布局，不使用外层 `L` 派生。
3. **探针 + Reftest**：等宽 CJK 文本退化为第一子行 `ceil(n/2)`、第二子行 `floor(n/2)`；比例字体按实测宽度平衡，不按字符数机械均分。
4. **探针 + Reftest**：每个片段取能排下的最大字素簇前缀，并独立实测平衡；子行内部不再折行。
5. **探针 + Reftest**：`B ≤ H0` 时注文不撑高外层行；`B > H0` 时行高为 `B + 2G`，注文盒前后各保留 `G`，相邻撑高行之间保留 `2G`。
6. **探针 + Reftest**：`n = 1`、奇数字、空注文三种边界。
7. **探针 + Reftest**：跨 2 行、跨 3 行以上时，片段顺序与 DOM 顺序一致。
8. **探针 + Reftest**：作者设置 `margin`／`padding`／`border` 时，首片段、中间片段、末片段分别承担正确的 inline 边缘；block 边缘每个片段都有；背景和边框按 `box-decoration-break` 绘制。
9. **探针 + Reftest**：`font-size`／`line-height` 的声明、继承、百分比／无单位行高和 `normal` 均与普通行内内容一致；夹注只把这些普通 computed 结果作为两条子行的输入。
10. **探针 + Reftest**：非 CJK、比例字体、组合字符和 RTL 文本均按普通 shaping 测量；使用两子行的实际测量宽度，不套用 `ceil(n/2) × f`。字符数较多的第一子行可以比第二子行更窄。
11. **探针 + Reftest**：注文到达外层行尾时，同一段文字作为普通行尾和作为夹注子行时，断行机会、标点禁则、autospace、spacing-trim、悬挂标点和 bidi 结果一致；只有字号、行高和可用 inline 尺寸不同。
12. **探针 + Reftest**：注文片段到达外层行尾，且该行按 `text-align`／`text-align-last` 的普通规则适用 justify 时，注文 margin box 到达外层行尾，两条子行均铺满扣除注文 inline 装饰后的剩余宽度；未到达行尾，或在 `text-align-last: auto` 下属于最后一行／强制换行行时，子行保持自然宽度，不 justify、不悬挂标点。到达行尾时，`hanging-punctuation`／`text-spacing-trim` 与普通行尾一致。
13. **探针 + Reftest**：整行只有夹注且该行不是最后一行时，执行 `text-align: justify`，注文盒必须到达外层行尾；若它就是最后一行，`text-align-last: auto` 下保持自然宽度，只有 `text-align-last: justify` 才拉满。无论是否 justify，最后一行仍按夹注自身行尾处理 `hanging-punctuation: last`、`force-end`、`allow-end`。
14. **探针 + Reftest**：夹注因后续字素放不下而截断时，即使还剩余少量宽度或该行不是段落最后一行，也执行行尾 justify／悬挂；双行切分和外层片段边界不得把逗号、句号等禁则标点放到行首。
15. **探针 + Reftest**：夹注内部声明行间注时，夹注仍只有两条子行，内部不得出现行间注流；该注文出现在对应正文片段的注文流中，并按其零宽位置映射的 `P` 参与中点定位、冲突推进和续行，同时保留原 DOM 位置的 computed style；`writing-mode`／`direction` 改用正文块容器的值。

<style>
  .page { writing-mode: vertical-rl; font-size: 16px; line-height: 1.5; }
  .note { -hutu-note-placement: inline; font-size: 0.5em; line-height: 1; }
</style>
<p class="page">司馬相如者，蜀郡成都人也，字長卿<span class="note">案：長卿，相如之字也。</span>。</p>
