# 中文注文排版规范（总纲）

> 状态：草案 v0.1（2026-10-30）
> 适用：Hutu 渲染引擎
> 范围：行内夹注、行间注、边注（眉批／地脚批）的标记、几何、断行与降级行为
> 非范围：脚注／尾注的编号与引用、注文自动编号、分页机制本身、注文内容的语义校验

本规范只描述**排版行为**，不描述实现。三个分册各自给出完整的几何规则与验收点：

| 分册 | 内容 |
|---|---|
| [inline_zh_CN.md](inline_zh_CN.md) | 行内夹注（双行注） |
| [interline_zh_CN.md](interline_zh_CN.md) | 行间注（push／squeeze） |
| [margin_zh_CN.md](margin_zh_CN.md) | 边注：眉批与地脚批 |

## 1. 术语与规范用语

- **锚点**（anchor）：承载注文的行内元素。注文是它的子元素。
- **注文元素**（note element）：声明了 `-hutu-note-placement` 的元素。
- **注文盒**（note box）：注文元素生成的、脱离普通行内流的盒。
- **inline 轴／block 轴**：按注文**自身**的书写模式解释。横排 `horizontal-tb` 的 inline 轴向右、block 轴向下；竖排 `vertical-rl` 的 inline 轴向下、block 轴向左。本文以 `vertical-rl` 举例；`vertical-lr` 时左右互换，一切规则按 block-start／end 解释，不按物理左右。
- **天头／地脚**：block-start 侧／block-end 侧的边注区。
- **子行**：夹注内部并排的两条小字行；靠 block-start 的为第一子行（竖排为右列，横排为上行）。
- **格**（cell）：夹注的一个半字宽推进单位，容纳两个排版字符；注文为奇数字时第二子行留半格空。

规范用语：**必须**（must）、**不得**（must not）、**应该**（should）、**可以**（may）、**建议**（recommended，非规范）。

## 2. 统一模型

### 2.1 结构

注文元素必须是锚点的**后代**，通常紧随被注文字：

```html
<p>正文正文<span class="anchor">被注文字<span class="note">注文内容</span></span>正文正文</p>
```

### 2.2 落位

三种注由 `-hutu-note-placement` 选择：

```css
.note { -hutu-note-placement: inline; }      /* 夹注 */
.note { -hutu-note-placement: interline; }  /* 行间注 */
.note { -hutu-note-placement: margin; }     /* 边注 */
```

`none` 表示不生成注文盒，注文按普通行内内容参与排版。

> `inline` 指“行内夹注”，与 CSS 的 `display: inline` 无关；`interline`、`margin` 同理只是本规范的落位名。

### 2.3 与普通行内流的关系

1. 注文盒不按普通行内文字参与排版；它按各自分册的规则参与行内推进或占位。
2. 除分册另有规定外，注文盒**不得**改变锚点所在行的行高。
3. 注文元素自身的 `display` 不决定注文盒类型（`display:none` 除外）；`position`、`float` 被忽略。
4. 注文元素的书写模式与 `direction` 继承锚点；注文的 inline／block 轴按注文自身书写模式解释。
5. 注文内部仍是正常行内内容，可以包含 ruby、着重号等，但受 §4.2 与各分册限制。

### 2.4 盒装饰

注文元素上作者声明的 `margin`、`padding`、`border`、`background` **全部尊重**，按普通盒模型参与几何。默认 UA 样式不添加任何装饰，因此默认无空隙。作者装饰可能破坏本规范假定的几何（例如把注文撑得比行还高），后果由作者承担。

### 2.5 默认字号

注文元素未声明 `font-size` 时**沿用继承值**。各分册给出建议比例（夹注 0.5em、眉批 0.5em），但均非强制。

## 3. 属性

| 属性 | 取值 | 初始值 | 继承 | 适用 |
|---|---|---|---|---|
| `-hutu-note-placement` | `none \| inline \| interline \| margin` | `none` | 否 | 行内元素 |
| `-hutu-note-fit` | `push \| squeeze` | `push` | 否 | 仅 `interline` |
| `-hutu-note-side` | `block-start \| block-end` | `block-start` | 否 | 仅 `margin` |
| `-hutu-note-align` | `start \| center \| end` | `start` | 否 | `interline`、`margin` |

解析规则：

1. 未知取值按**无效声明**处理：该声明被丢弃，属性保持初始值（因为不继承）。
2. 属性只对声明它的元素生效，**不继承**。祖先声明不会让后代变成注文。
3. 注文元素必须出现在行内上下文中；其 `display` 不影响注文盒类型。
4. `-hutu-note-fit` 在非 `interline` 上无效；`-hutu-note-side` 在非 `margin` 上无效；`-hutu-note-align` 在 `inline` 上无效。
5. 四个属性都是引擎自定义属性，不是 W3C 标准属性。
6. `-hutu-note-align` 在两种落位上含义不同：`interline` 是注文文字在通栏行内的对齐，`margin` 是注文整体沿边注区长轴相对锚点的对齐；详见各分册。

## 4. 通用行为

### 4.1 空注文

注文元素没有可排版内容（空文本、只有被 `display:none` 的内容）时**不得**生成注文盒，等价于 `none`。

### 4.2 嵌套

注文盒内部的 `-hutu-note-placement` **不生效**，按 `none` 处理；即注中之注按普通行内内容排。此条为暂定规则，见 §8。

### 4.3 选区与复制

注文按 **DOM 顺序**参与选区和复制，不因视觉重排而改变。其后果：

- 复制带注的正文时，注文文字会出现在锚点之后、正文继续之前。
- 边注虽然视觉上在页边，复制时仍按 DOM 位置夹在正文里。

### 4.4 回退

本规范**不要求**作者提供降级样式。不支持这些属性的引擎按 CSS 规则忽略未知属性，注文元素因此作为普通行内内容出现在 DOM 位置。这是可接受的降级，不是规范缺陷。

### 4.5 显示、打印与导出

屏幕、打印、导出使用同一套规则；本规范不定义分页本身。涉及分页的条款仅在宿主提供分页时生效（当前引擎尚未实现 `@page`）。

### 4.6 锚点消失

锚点元素或其注文元素被 `display:none`、从文档移除、或被 `content-visibility` 跳过时，注文盒随之消失，不留下占位。

## 5. 三章导航

| 章 | 关键约束 |
|---|---|
| 夹注 | 半字宽、两子行、占 `ceil(n/2) × f`、可跨行、不改行高 |
| 行间注 | 通栏小字块；push 撑开、squeeze 挤行距且溢出 |
| 边注 | 天头／地脚；继承书写模式；沿 block 轴换行与堆叠；放不下换边／换页／溢出 |

## 6. 决策记录

| 决定 | 取值 | 理由 |
|---|---|---|
| 标记方式 | 新 CSS 属性，注文为锚点子元素 | 语义集中、回退可读、不引入非标准元素 |
| 属性前缀 | `-hutu-note-*` | 明确是非标准实验特性，避免与未来标准撞名 |
| 夹注字号 | 由 `font-size` 决定，上限 `line-height / 2` | 保证两子行总高不超过行盒，规则可断言 |
| 夹注跨行 | 允许，继续半宽双行 | 古籍长注的常规形态；原子盒容不下长注 |
| 夹注奇数分配 | 第一子行（右／上）多一字 | 与传统双行夹注的阅读顺序一致 |
| 行间注宽度 | 通栏 | 独立成行的注文应占满整行，行为最可预测 |
| 行间注插入点 | 可插在段中任意行后 | 注文就在被注行之后，不必等到段末 |
| 眉批方向 | 继承正文书写模式 | 与正文一致；竖排时写满一列后向左换列 |
| 边注区 | 最近的非零 padding 祖先的 padding 区 | 复用现有盒模型，不新增属性 |
| 放不下 | 换边 → 换页（若有分页）→ 溢出 | 内容不丢，优先级明确 |
| 回退 | 不作要求 | 未知属性被忽略即为可读降级 |
| 复制 | 按 DOM 顺序 | 与无障碍阅读顺序一致 |

## 7. 已知风险与取舍

1. **没有分页**：`换页` 条款目前是休眠条款；连续滚动下最终一定落到“溢出”。
2. **默认字号继承**：夹注不写 `font-size` 时会被截到 `line-height / 2`（常见 0.75em），比传统的 0.5em 大；规范只能建议作者显式写 0.5em。
3. **竖排眉批很碎**：天头只有 1–2 字高时，眉批会写成很多短竖列再向左铺开；这是“继承正文 + 换列”的必然结果，不是 bug。
4. **装饰全部尊重**：作者一个 `padding` 就可能让夹注超出行盒；规范不阻止，但验收用例必须只用默认装饰。
5. **无外部标准可依**：WPT／Gecko 语料没有夹注／眉批用例；验收只能靠引擎自己的布局探针。
6. **复制顺序**：边注文字会混进正文复制流；这是“按 DOM 顺序”的直接后果，需在样例与文档中明示。
7. **内层 padding 抢边注区**：按“最近的非零 padding 祖先”规则，正文内层容器只要有 padding，眉批就会贴到那一层而不是页面边；作者应把留白集中写在页面容器上。

## 8. 开放问题

以下条目尚未定案，实现前必须逐条确认。部分条目在各分册已有标为“暂定”的行为，确认后从本表移除。

1. 嵌套注文：现定为“内层无效”，是否改为“允许一层”或“报错”。
2. 夹注出现在 `rt` 内：现定为“不生效”；夹注内出现 ruby 则允许。
3. 行间注的字号是否设上限（目前无上限，只建议 ≤ 正文）。
4. 夹注内的 `<br>`：按普通行内换行（结束当前片段）还是按强制换格处理。
5. 分页宿主下“换页”的细节：注文跨页时是否需要在下一页重复锚点标记。
6. 多栏（multicol）页面里边注区的选择：当前规则可能选到内层分栏容器。
7. `text-emphasis`、`text-decoration`、`text-spacing-trim`、`hanging-punctuation` 是否作用于注文内部。
8. 夹注片段的最小格数：行末只剩一格时是排一格还是整体移到下一行。
9. 锚点为 `float` 或绝对定位元素时，边注区的参照容器。
10. 夹注在 RTL 文本中的子行顺序：是否仍按 block-start／end。

## 9. 验收

### 9.1 可断言的量

- 夹注：注文盒的 inline 推进、block 尺寸、子行字符分配、断行位置、父行行高不变。
- 行间注：注文块每行的通栏尺寸、push 后后续内容的位移、squeeze 的可用空隙与溢出。
- 边注：边注区矩形、注文整体沿长轴相对锚点的对齐、换行方向、堆叠顺序、换边／溢出。

### 9.2 测试方式

文字宽度随字体变化，**不得**用像素级 reftest 断言文字位置。使用布局探针（`src/Hutu.Tests` 的单元／探针测试）断言几何量；像素级用例只用于纯色块与边框。

### 9.3 语料

`samples/Sample.Common/Samples/Pages/vertical-large.htm`（史記·司馬相如列傳）已有“正文 + ㊀ 标号 + `p.note` 注文段”的结构，可以改造成三种注的验收样例；改造后的样例只用于人工目视与探针，不进入像素断言。
