# 中文注文排版规范（总纲）

> 状态：草案 v0.7（2026-11-02）
> 适用：Hutu 渲染引擎
> 范围：行内夹注、行间注、边注（旁注／眉批／地脚批）的标记、几何、断行与降级行为
> 非范围：脚注／尾注的编号与引用、注文自动编号、分页机制本身、注文内容的语义校验

本规范只描述**排版行为**，不描述实现。三个分册各自给出完整的几何规则与验收点：

## 1. 术语与规范用语

- **注文位置**（note position）：注文元素在 DOM 顺序中的位置。注文元素不生成普通行内盒；该位置即三种注文的唯一定位依据。
- **注文元素**（note element）：声明了 `-hutu-note-placement` 的元素。
- **注文盒**（note box）：注文元素生成的、脱离普通行内流的盒。
- **inline 轴／block 轴**：行内夹注按注文**自身**的书写模式解释。边注和行间注按**正文块容器**的书写模式解释，注文自身的 `writing-mode`／`direction` 不参与布局。横排 `horizontal-tb` 的 inline 轴向右、block 轴向下；竖排 `vertical-rl` 的 inline 轴向下、block 轴向左。本文以 `vertical-rl` 举例；`vertical-lr` 时左右互换，一切规则按 block-start／end 解释，不按物理左右。
- **line-over／line-under**：行盒在 block 轴上的两侧。横排的 line-over 是上方；`vertical-rl` 的 line-over 是右侧；`vertical-lr` 的 line-over 是左侧。
- **行间注槽**：一条正文行在 line-over 侧对应的一条注文行空间。每个正文行最多占用一个注文槽；注文流在当前槽排满后继续使用下一条正文行的槽。
- **天头／地脚**：边注位于正文 inline-start／inline-end 侧时的传统称谓；竖排为上边／下边，横排的对应落侧为左边／右边。
- **子行**：夹注内部并排的两条小字行；靠 block-start 的为第一子行（竖排为右列，横排为上行）。

规范用语：**必须**（must）、**不得**（must not）、**应该**（should）、**可以**（may）、**建议**（recommended，非规范）。

## 2. 统一模型

### 2.1 结构与注文位置

注文元素直接写在需要插入注文的位置，不要求包裹被注文字，也不要求额外的父级元素：

```html
<p>正文正文<span class="note">注文内容</span>正文正文</p>
```

- 注文元素必须处于行内格式化上下文中。它不生成普通行内盒；其 DOM 位置作为零尺寸的注文位置参与排版。
- 注文位置是三种注文的唯一定位依据，不引入额外的父级元素或注文范围。
- 注文位置决定夹注的插入位点、行间注所在的注文行，以及边注所属的正文行；边注起点按该行的 block-start 定位，具体排布见边注分册。
- 行间注和边注的零宽位置正好落在软换行边界时，归入前序行内内容所在的行；若它位于行首、硬换行之后或块的起始位置，则归入后续行内内容所在的行；若块内没有其它行内内容，则生成一条空行作为注文所在行。
- 夹注参与普通行内断行；夹注第一个实际放置的片段所在的行就是注文所在行。
- 同一注文位置存在多个注文元素时，按 DOM 顺序处理。

### 2.2 落位

三种注由 `-hutu-note-placement` 选择：

```css
.note { -hutu-note-placement: inline; }      /* 夹注 */
.note { -hutu-note-placement: interline; }  /* 行间注 */
.note { -hutu-note-placement: margin; }     /* 边注 */
```

`none` 表示不生成注文盒，注文按普通行内内容参与排版。

> `inline` 指“行内夹注”，与 CSS 的 `display: inline` 无关；`interline`、`margin` 同理只是本规范的落位名。

### 2.3 与普通行内流的关系

1. 注文盒不按普通行内文字参与排版；它按各自分册的规则参与行内推进或占位。
2. 行间注和边注不得改变注文所在行的行高；行内夹注的 block 尺寸参与行高计算，具体见夹注分册。
3. 注文元素自身的 `display` 不决定注文盒类型（`display:none` 除外）；`position`、`float` 被忽略。
4. 行内夹注的书写模式与 `direction` 按 CSS 继承规则取得，其 inline／block 轴按注文自身书写模式解释。边注和行间注强制使用正文块容器的 `writing-mode`／`direction`，注文自身的对应声明不参与注文布局。
5. 注文内部仍是正常行内内容，可以包含着重号等普通行内内容；ruby 等复杂结构是否支持由各分册限定。

### 2.4 盒装饰

注文元素上作者声明的 `margin`、`padding`、`border`、`background` **全部尊重**，并按各注文类型的盒模型参与几何。行间注中的单个注文按 `display: inline` 处理：`margin-inline-start`／`margin-inline-end` 参与行内推进，`margin-block-start`／`margin-block-end` 对布局无影响；其余行内 padding、border、background 和分片绘制按普通行内盒规则处理。默认 UA 样式不添加任何装饰，因此默认无空隙。作者装饰可能破坏本规范假定的几何，后果由作者承担。

### 2.5 默认字号

注文的 `font-size` 和 `line-height` 完全按普通 CSS 级联、继承和 computed value 规则取得。引擎不为注文另算字号或行高；需要 0.5em 等传统比例时由作者显式声明。

## 3. 属性

| 属性 | 取值 | 初始值 | 继承 | 适用 |
|---|---|---|---|---|
| `-hutu-note-placement` | `none \| inline \| interline \| margin` | `none` | 否 | 行内元素 |
| `-hutu-note-side` | `auto \| inline-start \| inline-end` | `auto` | 否 | 仅 `margin` |

解析规则：

1. 未知取值按**无效声明**处理：该声明被丢弃，属性保持初始值（因为不继承）。
2. 属性只对声明它的元素生效，**不继承**。祖先声明不会让后代变成注文。
3. 注文元素必须出现在行内上下文中；其 `display` 不影响注文盒类型。
4. `-hutu-note-side` 在非 `margin` 上无效。
5. 这两个属性都是引擎自定义属性，不是 W3C 标准属性。

## 4. 通用行为

### 4.1 空注文

注文元素没有可排版内容（空文本、只有被 `display:none` 的内容）时**不得**生成注文盒，等价于 `none`。

### 4.2 嵌套

嵌套注文采用白名单：

1. 行内夹注内部的 `interline` 提升到外层夹注片段所在正文行的共享注文流。
2. 行内夹注内部的 `margin` 提升到页面边注区；其声明行是外层夹注片段中包含该零宽位置的那条正文行。
3. 行间注内部的 `margin` 提升到页面边注区；其声明行是包含该零宽位置的行间注槽所对应的正文行。

- 被提升的行间注和边注在原注文内容中保留零宽位置，不占原注文的行内推进，也不在内部另建注文流或边注区。
- 被提升注文保留原 DOM 位置计算出的 CSS computed style；`writing-mode`／`direction` 仍按对应注文类型改为正文块容器的值。
- 边注内部的任何注文、行内夹注内部的行内夹注、行间注内部的行间注或行内夹注定义均不生效，按普通节点参与外层注文的行内排版；其注文属性和注文落位行为被忽略。
- 本表以外的嵌套组合同样按普通节点处理，不得生成新的嵌套注文流或边注区。

### 4.3 选区与复制

注文按 **DOM 顺序**参与选区和复制，不因视觉重排而改变。其后果：

- 复制带注的正文时，注文文字会出现在其 DOM 位置，正文随后继续。
- 边注虽然视觉上在页边，复制时仍按 DOM 位置夹在正文里。

### 4.4 回退

本规范**不要求**作者提供降级样式。不支持这些属性的引擎按 CSS 规则忽略未知属性，注文元素因此作为普通行内内容出现在 DOM 位置。这是可接受的降级，不是规范缺陷。

### 4.5 显示、打印与导出

屏幕、打印、导出使用同一套规则；本规范不定义分页本身。只有明确写明“分页宿主”的条款才读取分页信息；边注不读取宿主分页状态（当前引擎尚未实现 `@page`）。

### 4.6 注文消失

注文元素被 `display:none`、从文档移除、或被 `content-visibility` 跳过时，注文盒随之消失，不留下占位。

## 6. 决策记录

| 决定 | 取值 | 理由 |
|---|---|---|
| 标记方式 | 新 CSS 属性，注文元素的位置即定义点 | 不需要额外容器，回退可读，不引入非标准元素 |
| 属性前缀 | `-hutu-note-*` | 明确是非标准实验特性，避免与未来标准撞名 |
| 夹注字号与行高 | 完全使用普通 CSS computed `font-size`／`line-height`；声明、继承、百分比、无单位值和 `normal` 均按普通规则 | 不在注文上叠加第二套尺寸算法，作者和嵌套标记的行为可预测 |
| 夹注跨行 | 允许，每个外层片段继续使用两个普通子行 | 古籍长注的常规形态；原子盒容不下长注 |
| 夹注双行分配 | 在每个字素边界实测两行宽度，取较小最大宽度；平局时第一子行（右／上）多放字素 | 比例字体不能按字符数均分；平局仍保持传统阅读顺序 |
| 夹注排版核心 | 与普通行内内容共用 computed 尺寸、断行、禁则、挤压、悬挂、bidi 和 shaping | 基础排版规则只实现一次，夹注只覆盖几何和落位 |
| 夹注行高 | 子行使用普通 computed values；`B = H1 + H2 + 装饰`。`B ≤ H0` 时保持 `H0`，`B > H0` 时使用 `B + 2G`，`G = max(0, (L - F) / 2)` | 注文尺寸完全传统化；撑开外层行时仍保留正文行间空隙 |
| 夹注行尾效果 | 只有片段到达外层行尾且该行按普通规则需要 justify 时才拉到外层行尾，并按普通规则悬挂标点；最后一行服从 `text-align-last` | 中途片段不表现为行尾，最后一行也不被错误地强制 justify |
| 纯夹注行／截断 | 整行可见内容都是夹注，或注文因放不下下一字素而被截断时，非最后一行按夹注自身行尾执行 justify 和标点规则；最后一行在 `text-align-last: auto` 下保持自然宽度 | 不能因自然宽度不足而漏掉非最后一行的行尾对齐，也不能把最后一行错误拉满 |
| 行间注宽度 | 每个注文槽使用对应正文行位置避让浮动后的 `W_i`；单条注文保留自然 inline 尺寸 | 注文槽必须像正文行一样避开浮动，溢出进入下一槽 |
| 行间注插入点 | 可关联段中任意行 | 注文流放在该行的 line-over 侧，不必等到段末 |
| 行间注侧 | 注文所在行的 line-over／block-start 侧 | 横排在上、`vertical-rl` 在右，符合行间注位于正文行之间的阅读关系 |
| 行间注起点定位 | 注文首次进入注文流时从声明位置开始；冲突、越界或续行时以流式推进为准 | 起始位置直接指向被注位置，正文中的定义点就是注文起点 |
| 行间注流影响 | 只有 push；每个正文行至多增加一条注文行，溢出继续到下一正文行的注文槽 | 保持正文行与注文行一一夹排，不在同一正文行前堆积多条注文 |
| 行间注字号与行高 | 完全使用普通 CSS computed `font-size`／`line-height` | 与夹注一致，不按正文尺寸压缩或另算 |
| 行间注书写模式 | 强制使用正文块容器的 `writing-mode`／`direction`；注文元素自身的对应声明忽略 | 一条共享注文流不能同时存在多个书写轴或 base direction |
| 行间注文字对齐 | 只采用正文块容器的 `text-align: justify`，且仅在注文行自然到达行尾时执行；其它 `text-align` 和 `text-align-last` 不影响注文流 | 避免中心／尾对齐平移已锚定的注文，也避免最后一行被强制拉满 |
| 行间注定位空白 | 起点定位和后续锚点产生的定位空白固定，不参与 justify 拉伸 | 保持注文与声明位置的对应关系；普通文本空格仍按普通规则处理 |
| 行间注盒模型 | 单个注文按 `display: inline` 处理 | `margin-inline-*` 有效，`margin-block-*` 忽略，其他装饰按普通行内盒规则绘制 |
| 注文与正文间距 | 注文行与目标正文行之间取 `max(G_note, G_body)`，其中 `G = (line-height - font-size) / 2`；注文与前一正文行的间距不调整 | 注文贴近被注正文，同时不挤压前一行已有的行间距离 |
| 行间注分片 | 可在注文槽之间正常分页；每个槽的最后一条注文行与对应目标正文行尽量同页 | 保持长注文流可排，同时避免正文行与紧邻注文被拆开 |
| 行间注 text-indent | 注文流自身不产生 `text-indent`；目标正文为第一行时，不得使用该行缩进占掉的 inline 区间 | 缩进属于正文首行，不应变成注文的额外起始缩进，也不应被注文覆盖 |
| 行间注排版核心 | 多个注文合并为一条连续注文流，与正文和夹注共用断行、禁则、挤压、悬挂、bidi 与 shaping | 防止注文边界割裂排版规则，也避免维护第二套文字排版实现 |
| 边注书写模式 | 强制使用正文块容器的 `writing-mode`／`direction`；注文元素自身的对应声明忽略 | 边注落侧、行内方向、换行和堆叠必须共享正文的一套轴 |
| 边注侧 | 按正文块容器的 inline-start／inline-end 解析；横排为左／右，竖排为上／下 | 边注位于正文行起始／结束方向的页边，不把竖排的天头地脚误当成 CSS block 轴 |
| 边注 auto | 比较根元素 `html` 两侧 margin 沿正文 inline 轴的静态厚度，取较大者；相等取 `inline-start`；已放置边注不影响选择 | 不声明侧时稳定地优先使用更宽的横排左右页边或更高的竖排上下页边 |
| 边注区 | 页面／初始包含块边缘到 `html` border box 之间的对应侧 margin | 边注落在页面自身的空白 margin 中，不被 `body` 或正文内层元素的 margin／padding 抢走 |
| 边注堆叠 | 同侧按声明行 line box 的正文 block 轴位置排序，同一行再按 DOM 顺序 | 视觉边注顺序跟随正文行顺序，不受浮动、表格或定位造成的 DOM 顺序偏差影响 |
| 边注盒模型 | 自然流式块；`width:auto` 使用边注区可用 inline 尺寸，不做 shrink-to-fit；margin box 参与堆叠 | 不引入内容宽度测量和收缩算法，边注与普通块的自然断行保持一致 |
| 边注排版核心 | 复用普通行内断行、禁则、挤压、悬挂、bidi、shaping 和文本装饰，只替换可用宽度、外部起点与书写轴来源 | 基础排版规则只实现一次，边注不维护第二套文字处理逻辑 |
| 边注 text-indent | 使用注文元素的 computed `text-indent`，按普通 CSS 继承；只影响边注组第一条格式化行（列） | 和普通属性一致，既不特殊借用正文行 used value，也不额外屏蔽正常继承 |
| 边注 text-align | 使用注文元素的 computed `text-align`，按普通 CSS 继承，在注文自身可用 inline 尺寸内排版 | 正文行最终的 used value 不覆盖边注属性，但正常继承链仍然有效 |
| 边注起点 | 注文组的 block-start margin edge 对齐声明行 line box 的 block-start；不提供额外的注文对齐属性 | 边注从被注正文行的位置开始展开，定位确定且可直接断言 |
| 边注延伸 | 不设 block 轴容量判定；内容一直沿正文 block-end 排列，越过边注区也不换侧 | 边注是自然流，不因长度、堆叠冲突或页面边界改变作者选择的侧 |
| 嵌套注文 | 仅支持夹注内行间注、夹注内边注、行间注内边注提升；边注内任何注文、夹注内嵌套夹注及其余组合均按普通节点处理 | 支持有明确落位路径的组合，避免在已脱离普通流的注文内部再创建平行注文流或边注区 |
| 回退 | 不作要求 | 未知属性被忽略即为可读降级 |
| 复制 | 按 DOM 顺序 | 与无障碍阅读顺序一致 |

## 7. 已知风险与取舍

1. **边注越过页面边界**：边注可以沿正文 block-end 一直延伸并越过普通页面边界，页面边界不触发换侧或重新归属；可见性由普通 overflow 规则决定。
2. **缺省尺寸完全继承**：夹注不写 `font-size` 时继承正文字号，不写 `line-height` 时继承正文行高，通常会明显大于传统 0.5em 夹注；需要传统效果时由作者显式声明。
3. **竖排眉批很碎**：天头只有 1–2 字高时，眉批会写成很多短竖列再向左铺开；这是“继承正文 + 换列”的必然结果，不是 bug。
4. **装饰全部尊重**：作者一个 `padding` 就可能撑高夹注所在行；行高按 `B + 2G` 计算，注文前后各保留正文行间空隙。
5. **无外部标准可依**：WPT／Gecko 语料没有夹注／眉批用例；验收只能靠引擎自己的布局探针和 Reftest。
6. **复制顺序**：边注文字会混进正文复制流；这是“按 DOM 顺序”的直接后果，需在样例与文档中明示。
7. **根 margin 为零**：`html` 没有对应侧 margin 时边注区厚度为零，边注只能从根边界起自然延伸；作者需要页面留白时必须显式设置 `html` 的 margin。

## 8. 开放问题

以下条目尚未定案，实现前必须逐条确认。部分条目在各分册已有标为“暂定”的行为，确认后从本表移除。

1. 行间注的字号是否设上限（目前无上限，只建议 ≤ 正文）。
2. `text-emphasis`、`text-decoration`、`text-spacing-trim`、`hanging-punctuation` 在不同注文类型中的内部作用范围。
3. 注文位于 `float` 或绝对定位元素内时，边注区的参照容器。
4. 夹注在 RTL 文本中的子行顺序：是否仍按 block-start／end。

## 9. 验收

### 9.1 可断言的量

- 夹注：注文盒的 inline 推进、block 尺寸、实测双行切分、断行位置、注文参与后的所在行行高，以及仅限外层行尾的 justify／标点悬挂。
- 行间注：单条注文的起点定位、正文书写模式／direction 的强制采用、逐槽浮动避让后的 `W_i`、注文溢出到下一正文行槽的位置、实际行数与行高、非伸缩定位空白、注文与正文的 half-leading 间距、行内盒几何、分页位置，以及 push 后正文行的位移。
- 边注：边注区矩形、`auto` 选侧、注文组 block-start 与声明行 line box block-start 的对齐、自身 `text-indent`／`text-align`、换行方向、固定落侧后的自然流式延伸和堆叠顺序。

### 9.2 测试方式

采用三层测试，各层职责不得互相替代：

1. **布局探针**：使用 `src/Hutu.Tests` 的单元／探针测试断言精确几何量。探针是尺寸、位置、断行和溢出规则的权威依据。
2. **Reftest**：在同一进程、同一引擎、同一机器、同一视口、同一缩放比例下渲染测试页与参考页，比较裁剪后的渲染区域。两边必须使用相同的书写模式、字号、颜色和背景。
3. **纯盒像素比较**：注文只涉及纯色块、边框或背景时，使用无文字容差的精确比较。

Reftest 规则：

- 通过 `@font-face` 加载仓库内置的固定版本测试字体，禁止回退字体和字体合成，并确保截图前字体已加载。测试页与参考页必须使用同一字体文件。
- 参考页只使用稳定原语（例如绝对定位、普通块盒和固定字号）构造预期结果，**不得**复用正在测试的 `-hutu-note-*` 特性。
- 比较区域必须裁剪到测试区域，不对整页计算差异比例。
- 文字区域允许有限的单通道差异和差异像素数量上限，容差参数按平台校准；容差只用于吸收抗锯齿与光栅化噪声，**不得**用于接受布局位移。
- 纯色块、边框和背景区域不使用文字抗锯齿容差。
- Reftest 的测试页与参考页必须在同一环境中实时渲染。不得直接比较跨机器、跨操作系统或跨引擎版本的 golden image；如需保存 golden image，必须按平台和引擎版本分别建立基线。

每一条验收点必须标记测试类型：**探针**、**Reftest** 或 **探针 + Reftest**。精确几何由探针断言，整体视觉与特性交互由 Reftest 验证。

### 9.3 语料

`samples/Sample.Common/Samples/Pages/vertical-large.htm`（史記·司馬相如列傳）已有“正文 + ㊀ 标号 + `p.note` 注文段”的结构，可以改造成三种注的验收样例。改造后的样例可用于人工目视、布局探针和 Reftest 测试页；Reftest 参考页必须另行使用稳定原语构造。
