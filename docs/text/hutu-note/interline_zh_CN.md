# 行间注

> 总纲见 [overview_zh_CN.md](overview_zh_CN.md)。本册只描述 `-hutu-note-placement: interline`。

## 1. 触发与结构

```css
.note {
  -hutu-note-placement: interline;
}
```

- 注文元素必须处于行内格式化上下文中。
- 同一行间注区域内的多个注文共同生成**一条连续注文流**；每个注文元素按 DOM 顺序向该流贡献普通行内内容，不再各自生成相互堆叠的注文块。
- 每条正文行在 line-over 侧最多对应**一条注文行**（一个注文槽）。注文流沿 inline 轴使用该槽的最终可用区间；当前槽排满后，剩余内容继续进入下一条正文行的注文槽，而不是在同一正文行前再堆一条注文。
- 行间注只有 **push** 一种落位方式：注文槽插在对应正文行的 line-over／block-start 侧，并推动该正文行及其后续内容。
- 行间注不得压缩自身字号、行高或其它盒尺寸去挤进相邻两行之间，也不得以覆盖后续行的方式排版。
- 注文流不整体继承正文的 `text-align`。只有正文块容器的 computed `text-align` 为 `justify` 时，才对真正自然到达行尾的注文行执行行尾 justify；`start`／`center`／`end` 等声明不影响注文流位置。
- 注文流的 `writing-mode`／`direction` 强制取正文块容器的值；注文元素及其内部 run 不建立另一套书写模式或 base direction。
- 注文流必须复用普通行内排版核心，不单独实现断行、标点禁则、标点挤压、标点悬挂、两端对齐、bidi 或 shaping。

### 1.1 位于行内夹注内

- 行内夹注内部的 `-hutu-note-placement: interline` 必须提升到正文层，进入外层夹注片段所在正文行的共享注文流。
- 夹注内部不得再创建独立的行间注流，也不得把行间注排在两条子行之间。夹注仍只包含原来的两条子行。
- 被提升的注文在原夹注内容中的位置保留为零宽注文位置，不占两条子行的 inline 推进；它的正文内容只进入正文层的注文流。
- 被提升注文所属的正文行，是外层夹注中包含该零宽位置的那个正文片段所在行。外层夹注跨多个正文行时，不统一提升到首行或末行。
- 被提升注文在正文行上的声明坐标 `P`，按该零宽位置在夹注子行中的实际 inline 偏移映射到外层夹注片段的正文 inline 区间。
- 被提升注文保留其原 DOM 位置计算出的 CSS computed style；字号、行高和继承结果不因提升而重新计算，但 `writing-mode`／`direction` 统一改用正文块容器的值。
- 同一正文行中，被提升注文与正文直接声明的行间注按注文位置的 inline／DOM 顺序接入同一条注文流。
- 被提升注文仍遵守本册的全部规则，包括起点定位、冲突推进、按正文行槽续行、push 和普通行内排版核心。

### 1.2 位于行间注内

- 行间注内部的 `-hutu-note-placement: margin` 提升到页面边注区，不进入行间注流，也不占注文行的 inline 推进。
- 被提升边注的声明行，是包含该零宽位置的行间注槽所对应的正文行。边注从这个正文行的 block-start 建立位置，并按边注分册的规则独立延伸。
- 被提升边注保留原 DOM 位置的 CSS computed style；`writing-mode`／`direction` 改用正文块容器的值。
- 边注内部再声明的边注、行间注或行内夹注均不生效，按普通行内节点参与边注内容排版。
- 行间注内部再声明行间注或行内夹注时，定义同样不生效，按普通行内内容参与当前注文行。

## 2. 注文流位置与宽度

### 2.1 起点定位

- 注文位置在注文所在正文行上的 inline 坐标为 `P`。
- 一个注文首次进入当前注文槽时，其 inline-start margin edge 尽量取 `P`；`P` 本身就是起点，不按注文宽度反推中心位置。inline-start margin／padding／border 从 `P` 向外占用，文字 run 随后排在这些装饰之后。
- 若 `P` 早于当前槽已经排到的流游标，则从前序内容之后继续；若 `P` 超出当前槽的可用范围，则从当前槽能够到达的最近位置继续。前序内容包括同一条注文流中的其它注文。
- 注文因冲突或槽宽而换行后，后续片段从下一正文行的注文槽 inline-start 继续。
- 起点定位产生的段间空白是固定几何，不属于可伸缩空白，不参与 `text-align: justify`、word spacing 或其它空隙拉伸；注文文本自身的普通空格仍按普通行内规则处理。
- 只有当注文因后续内容不能继续放入而自然到达行尾，且正文块声明了 `text-align: justify` 时，才执行行尾两端对齐。注文自然结束、未到达行尾或正文没有声明 `justify` 时，注文流保持自然宽度，不为了填满行尾而拉伸。

### 2.2 逐行可用宽度

正文行 `i` 的注文槽按普通行盒参与同一块容器中的浮动避让，最终可用 inline 区间为 `[S_i, E_i]`，宽度为 `W_i`：

- 每个注文槽在自己的 block 位置避让当时仍占位的浮动，而不是统一沿用某一条正文行的宽度。
- 浮动使当前注文槽变窄时，该槽按 `W_i` 正常断行；放不下的后续内容进入下一正文行的注文槽。
- 无浮动时：注文所在块容器（多栏时为所在栏）的内容宽／高。
- 按正文书写模式取轴：正文竖排时取内容高；正文横排时取内容宽。
- 注文流中的每个注文按 `display: inline` 参与布局：`margin-inline-start`／`margin-inline-end`、inline padding 和 inline border 在推进中正常占据空间，`margin-block-start`／`margin-block-end` 对布局无影响。
- block 轴的 padding、border 和 background 按普通非替换行内盒保留并绘制，但不增加 line box 高度；其可见范围可以超出 line box，仍由普通绘制和 overflow 规则决定。
- 每个注文槽都在上述可用 inline 尺寸内按普通行内排版规则断行。
- `text-indent` 不缩进注文流的任何行；但若注文关联的是正文块的第一条格式化行，每条注文行的 `S_i` 都不得早于该正文行应用 `text-indent` 后的实际内容起点，注文不得进入首行缩进占掉的 inline 区间。
- 上述边界约束只针对首行已占用的区间，不是把正文的 `text-indent` 继承给注文；关联后续正文行时仍按各行自身的浮动避让结果取可用 inline 区间。

## 3. push 模式

### 3.1 位置

- 每个非空注文槽位于**对应正文行盒的 line-over／block-start 侧**：
  - 横排：位于注文所在行上方；
  - `vertical-rl`：位于注文所在行右侧；
  - `vertical-lr`：位于注文所在行左侧。
- 在块向顺序上，每个注文槽位于对应正文行之前：该注文行的 block-end 紧接目标正文行的 block-start。
- 加入注文槽时先按注文行高度 `h_i` 占位；注文再与正文侧的有效边界产生 `O_i` 的重叠，并使正文行向注文方向移动 `A_i`，所以正文行相对无注文时的净位移为 `h_i - A_i`。
- 同一条注文流可以占用多个正文行的注文槽，因此整段正文会按实际占用的槽高逐行向 block-end 推移。
- 段落被切开，但仍是同一段落；缩进、断行、对齐和标点悬挂继续按原段落规则处理。
- 注文流不改变段落内其它正文行的断行位置；它只在对应行之前增加块向空间。

### 3.2 尺寸

| 量 | 值 |
|---|---|
| 注文槽 line box inline 尺寸 | 第 `i` 槽取对应正文行位置的 `W_i` |
| 注文槽 line box block 尺寸 `h_i` | 按普通行布局得到，使用该行各 run 自己的 computed `font-size`／`line-height` |
| 普通正文边界 | 无行内夹注时，有效边界是正文 line box 的 block-start；`O_i = min(G_note_i,G_body_i)`，`A_i=O_i` |
| 夹注第一子行边界 | 有行内夹注时，有效边界是夹注第一子行的 border-box block-start；设它距正文 line box 边界为 `S_i`，`O_i = min(G_note_i,G_inline-first)`，`A_i=S_i+O_i` |
| 注文与前一条正文行间距 | 保持两条普通相邻 line box 原有 leading，不做压缩 |
| 段落新增 block 尺寸 | 在正常一注文槽一条注文行时，为 `Σ h_i - Σ A_i`；槽耗尽后的退化见 §3.3 |

- `G = (line-height - font-size) / 2`。普通正文边界和行间注边界按 `min(G_note_i,G_body_i)` 重叠，最终保留 `max` 对应的 gap。
- 有行内夹注时，正文 line box 到第一子行边界之间的居中余量、block margin、border 和 padding 都汇总为 `S_i`。行间注先对齐到这个更靠内的夹注边界，再按 `O_i = min(G_note_i,G_inline-first)` 与它重叠；因此正文 line box 需要向注文移动 `A_i=S_i+O_i`。移动量大于正文 line box 高度时允许超出，不能改用外层正文 line box 的 `G_body` 顶替第一子行 gap。
- 同一正文行有多个行内夹注时，分别计算 `A_i=S_i+min(G_note,G_inline-first)`，取其中较小值作为该边界的正文移动量，避免任何一个第一子行被越过其允许重叠量。
- 注文之前的边界仍由两条现有 line box 的 leading 决定；引擎不额外插入空行或固定空隙。
- 注文行和正文行使用各自的 computed `line-height` 与 `font-size`；不得用正文行高反算注文行高，也不得把两者的 `G` 相加后重复计入。
- 遇到被双行夹注撑高的正文行时，使用撑高后的实际 line box 确定外层边界，但交界对齐改用第一子行的实际 block-start；不得回退到标称正文行高，也不得用外层膨胀后的 `G_body` 代替。

### 3.3 同一行多个注文

同一行内有多个行间注时，按注文位置在行内的 inline／DOM 顺序接入同一条注文流，不在注文之间另起块或增加引擎空隙。

1. 每条注文先尝试把首个字素放在 §2.1 的位置 `P`。
2. `P` 早于当前槽的流游标时，从前序内容之后继续；`P` 晚于游标时，插入固定定位空白并让注文从 `P` 开始。
3. 当前正文行的注文槽排满后，后续内容进入下一条正文行的注文槽；不能在同一正文行前再增加一条注文行。后续槽的普通续行从该槽可用 inline-start 开始。
4. 注文可以在普通断行机会处跨越槽边界。一个注文元素结束不等于注文行结束，续行仍按普通行内断行规则处理。

如果注文已经用到声明点之后的最后一条正文行槽而仍有剩余内容，规范把它视为**槽耗尽退化**：剩余内容只能继续占用最后一个槽并形成额外注文行，或在宿主支持时溢出到后续分片；不得把额外注文行伪装成“另一个正文行槽”。作者和测试应优先保证注文不超过其后的正文行数。

### 3.4 段落最后一行

注文位于块的最后一行时，注文流仍放在该行的 line-over 侧，并增加块的高度；注文所在行及其后内容按 block flow 方向移动，块之后的兄弟内容也随之移动。

## 4. 字号与行高

- 行间注**不定义**自己的字号或行高换算公式。注文元素及其内部内容的 `font-size`、`line-height` 完全按普通 CSS 级联、继承和 computed value 规则取得。
- 作者声明时使用声明值；未声明时使用普通继承值。不得用正文的字号或行高派生、缩放或截断注文字号／行高。
- `line-height: normal` 按普通字体行高规则解析为实际值；百分比、数值、长度和继承行为都与普通行内内容一致。
- 注文每一行都按普通行布局使用该行各 run 自己的 computed `font-size`／`line-height`。注文内部嵌套元素直接声明的尺寸只影响它自身的 run，并按普通行高规则参与该注文行的 `h_i`。
- 空注文行没有文字 run 时，以注文元素自身的 computed `line-height` 作为该行的基础高度。
- 注文行盒不得为了省空间而压到正文行高以内，也不得被强制等于相邻正文行的高度。
- 注文流自身的 line box 总高度按实际 `h_i` 计算，不按固定“一行”、注文个数或正文行高估算；段落净增高还要扣除每个目标正文行边界实际产生的正文移动量 `A_i`。
- 建议注文字号 ≤ 正文 `font-size`，但规范不设硬上限（见总纲 §8）。

## 5. 行内排版核心

- 注文流必须与正文、行内夹注复用同一套普通行内排版核心。引擎不得为行间注另写断行器或标点处理器。
- 字形整形、bidi、`white-space`、断行机会、标点禁则、`text-autospace`、`text-spacing-trim` 和 `hanging-punctuation` 都按普通行盒处理。
- 正文的 `text-align: justify` 只在注文行自然到达行尾时触发两端对齐；其它 `text-align` 值以及 `text-align-last` 不把注文流整体平移或强制拉满。普通文本内部的合法可伸缩空隙仍按行内排版规则处理，起点定位产生的固定空白不可伸缩。
- 一个注文元素结束不等于注文行结束。只有注文流真正到达某条注文行的行尾时，才按普通行尾规则处理标点悬挂；两端对齐还额外要求正文声明 `justify`，且该行是因后续内容放不下而自然换行。
- 注文元素边界不得自行生成空格、换行、段落边界或额外的断行机会；字符之间能否断行仍由前后实际内容和普通断行规则决定。
- 行间注与正文的差别只包括所在位置、可用 inline 尺寸和注文自身的 computed 样式；基础行排版规则必须相同。

## 6. 分片与分页

- 注文流参与普通块流分片，可以在相邻注文 line box 之间分页；不得在单个 line box 内部拆分。
- 最后一条注文 line box 与目标正文行应尽量留在同一页。两者放不下时，把这一组整体移到下一页，前面已经排定的注文行可以从更早的分片续排。
- 单行注文流与目标正文行作为一个不可拆的组合处理；多行注文流只对最后一行与目标正文行施加这个组合约束。
- 多栏及其它分片宿主按同样的普通分片规则处理；没有分页时沿用连续块流。

## 7. 与其它特性的交互

- **浮动**：每个注文槽在自己的 block 位置按普通行盒避让浮动，不覆盖浮动；浮动使槽变窄时，当前槽按实际 `W_i` 断行，剩余内容继续进入下一正文行槽，并把目标正文行及其后续内容按实际槽序列向 block-end 挤下去。
- **多栏**：每条注文行取所在栏在该 block 位置的实际可用 inline 区间，再按普通行盒避让浮动。
- **绝对定位**：注文元素上的 `position` 被忽略。
- **装饰**：单个注文按 `display: inline` 处理。`margin-inline-start`／`margin-inline-end` 参与推进，`margin-block-start`／`margin-block-end` 忽略；padding、border、background 和跨行分片按普通行内盒规则绘制。
- **`text-align`**：只读取正文块容器的 `justify`，且只在注文行自然到达行尾时执行行尾两端对齐；其它声明和 `text-align-last` 不移动或强制拉满注文流。

## 8. 验收点

> 类型标记：**探针** = 数值几何断言；**Reftest** = 与参考页做带文字抗锯齿容差的截图比较；**探针 + Reftest** = 两者均必须。

1. **探针**：正常槽序列中，注文行的 block 起点和正文行位移必须由 `h_i - A_i` 逐槽累加；无行内夹注时 `A_i=min(G_note_i,G_body_i)`，有行内夹注时 `A_i=S_i+min(G_note_i,G_inline-first)`，注文与前一正文行的边界不被压缩。
2. **探针**：每个注文槽使用自己 block 位置浮动避让后的 `W_i`；单个注文按 `display: inline` 参与布局。
3. **探针**：单条注文可完整排入一行且无冲突时，其 inline-start margin edge 与声明位置 `P` 重合；没有 inline-start margin／padding／border 时，第一个可见 run 也从 `P` 开始，而不是让注文盒中心与 `P` 重合。
4. **探针 + Reftest**：多条注文按 DOM 顺序处理；后一条注文的起点与前序内容冲突或越过槽边界时，从前序内容的流游标处继续或换到下一正文行槽，不覆盖前序内容。起点定位产生的段间空白保持固定，不因 `text-align: justify` 拉伸。
5. **探针 + Reftest**：行间注不得覆盖目标正文行或其它正文行；目标正文行之后的位移必须按槽序列计算，并保留目标正文行与其前一正文行原有的边界。
6. **探针 + Reftest**：同一行多个行间注进入同一条注文流，不为每个注文另起块；当前槽排满后必须续到下一正文行槽，不能在同一正文行前叠出第二条注文行。
7. **探针 + Reftest**：注文不改变目标正文行自身的高度；段中注文之后，段落后半段继续排布，缩进、断行与对齐不变。
8. **探针 + Reftest**：正文的 `text-align: start`／`center`／`end` 和平移类声明不改变注文流位置；只有 `text-align: justify` 且注文行真正自然到达行尾时才执行行尾两端对齐。`text-align-last` 不强制拉满注文行。
9. **探针 + Reftest**：多栏与竖排下每个注文槽使用所在栏在该位置的实际可用 inline 区间，不取整页宽度。
10. **探针 + Reftest**：长注在注文流中正常折成多行；在正文行槽充足时，每一条新注文行进入下一个槽，实际行数、槽号和位移不得按固定一行或注文个数估算。
11. **探针 + Reftest**：`font-size`／`line-height` 的声明、继承、百分比、无单位值、长度和 `normal` 均与普通行内内容一致；不为行间注额外压缩或放大。
12. **探针 + Reftest**：注文内嵌套元素改变自身字号／行高时，只按普通行高规则影响其所在注文行；空注文行使用注文元素自身的 computed `line-height`。
13. **探针 + Reftest**：单个注文按 `display: inline` 处理：`margin-inline-start`／`margin-inline-end` 参与推进，`margin-block-start`／`margin-block-end` 忽略；padding、border 和 background 按普通行内盒规则布局、绘制和跨行分片。
14. **探针 + Reftest**：同一段文字作为正文、行内夹注和行间注时，断行机会、标点禁则、`text-autospace`、`text-spacing-trim` 与 `hanging-punctuation` 结果一致；只有可用 inline 尺寸、字号和行高可以不同，行间注的书写模式必须与正文一致。
15. **探针 + Reftest**：一个注文元素在注文行中间结束时，不触发该注文自身末尾的两端对齐或标点悬挂；只有注文流真正到达行尾时才执行普通行尾规则。
16. **探针 + Reftest**：行内夹注内声明行间注时，其零宽位置不占夹注子行推进，夹注内部不生成行间注流；注文提升到包含该位置的外层正文片段所在行，按映射后的 `P` 加入该正文行的共享注文流，并保留原 DOM 位置的 computed style，但 `writing-mode`／`direction` 改用正文块容器的值。
17. **探针 + Reftest**：注文流可只在相邻注文 line box 之间分页；每个槽的最后一条注文 line box 与对应目标正文行尽量同页，放不下时整组移到下一页。
18. **探针 + Reftest**：无行内夹注时按正文 line box 边界和 `min(G_note,G_body)` 重叠；有行内夹注时以第一子行实际 border-box block-start 为边界，先计入居中/装饰偏移 `S`，再按 `min(G_note,G_inline-first)` 重叠并移动正文 `S+O`。同一行多个夹注取各自移动量的较小值。注文与前一条正文行的边界保留普通相邻 line box 的 leading。
19. **探针 + Reftest**：正文首行有 `text-indent` 时，关联该行的注文流不额外缩进，但其 inline-start 不得进入首行缩进占掉的区间；关联后续正文行时不受该缩进区间限制，只使用各行自身浮动避让后的可用区间。
20. **探针 + Reftest**：注文元素自身声明不同的 `writing-mode`／`direction` 时，注文流仍完全使用正文块容器的书写模式和 base direction；起点 `P`、续槽、页内推进和文字方向不因注文声明改变。
21. **探针 + Reftest**：浮动只覆盖部分注文槽时，各槽按自身 block 位置得到不同 `W_i`，不得覆盖浮动；因挤窄产生的额外注文行必须按槽序列计入布局，不能改变“每槽至多一条注文行”的正常规则。
22. **探针 + Reftest**：行间注内部声明边注时，边注不占注文行推进，提升到页面边注区，并以包含该零宽位置的槽所对应正文行作为声明行；行间注内部再声明行间注或行内夹注时，内层定义按普通节点忽略。
